# Problem Report 2026-04-23 22:32:40

## Scope

- API actual test group 01: User avatar deletion and Notice endpoints.
- Failed result file: `api-test-results-01-auth-user-asset-notice-20260423223210.md`.

## Symptoms

- `DELETE /users/{id}/avatar` returned HTTP 500.
- `GET /notices`, `GET /notices/unread`, `PATCH /notices/read`, and `PATCH /notices/unread` returned HTTP 500.

## Root Causes

- `delete_job.start_time` and `delete_job.finish_time` were defined as `NOT NULL` in `init.sql`, but a newly queued delete job is intentionally only `WAITING`; it has no start or finish time yet.
- The `notice.read` column name is a reserved word in the MariaDB/MySQL SQL dialect used by the test database. MyBatis-Plus generated SQL such as `read = ?`, which MariaDB rejected.

## Fix

- Updated `init.sql` so `delete_job.start_time` and `delete_job.finish_time` are nullable lifecycle timestamps.
- Escaped `Notice.read` with a MyBatis-Plus `TableField` annotation that emits the column as backtick-quoted `read`.
- Added regression coverage:
  - `DatabaseSchemaContractTest.deleteJobLifecycleTimestampsAreNullableUntilJobRuns`
  - `NoticeServiceUnitTest.readColumnIsEscapedBecauseReadIsReservedInMysqlFamilyDatabases`

- Re-run unit tests.
