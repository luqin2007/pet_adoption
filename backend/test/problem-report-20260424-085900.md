# Problem Report 2026-04-24 08:59

## Scope

- API group 03: item donation / medical
- API group 04: adopt / breading / volunteer

## Fixed Issues

1. `FollowRecordMapper.queryByTasks(...)` failed on empty sets
- Symptom: adopt and follow responses crashed before any follow record existed.
- Cause: `taskIds.iterator().next()` was called even when the set was empty.
- Fix: return an always-empty query when the input set is null or empty.

2. `AdoptBreadingFacade` batched follow-task assembly used unsafe empty-query paths
- Symptom: adopt list/detail and follow-task list could throw before follow records existed.
- Cause: facade code queried follow records even when there were no task ids; follow-task page also grouped records by the wrong key.
- Fix: skip the query for empty id sets and group follow records by `taskId`.

3. `VolunteerShiftResponse.createBatch(...)` used `shift.id` instead of `shift.taskId`
- Symptom: volunteer shift list/detail assembly could attach the wrong task or location.
- Cause: batch lookup keyed task/location by shift id.
- Fix: use `shift.getTaskId()` for task and location lookup.

4. Several MyBatis mappers were missing `getEntityClass()`
- Symptom: list/detail APIs crashed with `Invalid bound statement ... getEntityClass`.
- Affected mappers fixed here:
  - `AgreementFileMapper`
  - `VolunteerShiftStatusRecordMapper`
  - `VolunteerTaskMapper`
- Fix: implement `getEntityClass()` and missing message helpers where needed.

5. `VolunteerTask.location_id` schema was stricter than service flow
- Symptom: `POST /volunteers/shifts` failed with `Field 'location_id' doesn't have a default value`.
- Cause: service inserts `volunteer_task` first, then creates location, then updates `location_id`.
- Fix: change `volunteer_task.location_id` to nullable in `init.sql` and the live test database.

6. `AgreementUpdateRecord.content` schema was stricter than agreement lifecycle
- Symptom: paper agreement creation failed with `Field 'content' doesn't have a default value`.
- Cause: paper agreements legitimately have no text content.
- Fix: change `agreement_update_record.content` to nullable in `init.sql` and the live test database.

7. `AgreementFile.filename` / `Agreement.sign` columns were too short
- Symptom:
  - paper agreement creation failed with `Data too long for column 'filename'`
  - agreement signing failed with `Data too long for column 'sign'`
- Cause: generated asset filenames are much longer than `varchar(20)`.
- Fix: change both columns to `varchar(255)` in `init.sql` and the live test database.

8. `AdoptBreadingService.addAgreement(...)` assumed `fileOrder` was always non-null
- Symptom: electronic agreement creation failed with NPE.
- Cause: `fileOrder.size()` was called even for electronic agreements.
- Fix: normalize null `fileOrder` to `List.of()`.

9. API test script filename collisions during agreement upload/sign
- Symptom: duplicate-file `409` during paper-agreement append/sign tests.
- Cause: repeated uploads reused the same source image too quickly.
- Fix: use different files and a short delay in the group 04 script.
