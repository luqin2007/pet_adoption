# Problem Report 2026-04-23 22:29:10

## Scope

- API actual test group 01: Auth, User, Asset, Notice.
- Failed cases in `api-test-results-01-auth-user-asset-notice-20260423222610.md`.

## Symptoms

- After `PUT /users/{id}` changed the current user's username, subsequent authenticated requests using the previous access token returned HTTP 500.
- Affected follow-up cases included `USER-03`, `USER-04`, `USER-06`, and all Notice cases because the same stale token was reused.

## Root Cause

- Access tokens store the username as the JWT subject.
- After the username changes, the old token is still structurally valid, but `JwtAuthenticationFilter` calls `UserService.loadUserByUsername(oldName)`.
- `UsernameNotFoundException` escaped from the filter and was handled as a generic server error instead of being treated as an unauthenticated request.

## Fix

- Updated `JwtAuthenticationFilter` to catch Spring Security `AuthenticationException`, clear the security context, and continue the filter chain.
- Added `JwtAuthenticationFilterUnitTest.staleTokenForRemovedOrRenamedUserDoesNotEscapeAsServerError`.
- Updated the API test runner to explicitly verify the stale token is rejected, then re-login with the new username before testing avatar and notice endpoints.
