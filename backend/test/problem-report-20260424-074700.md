## Additional Findings

1. Converter-based query helpers in `MPLambdaQuery` evaluated converters too early.
   - Symptom:
     - `PUB-02` failed with `422 无效文章类型` even when `type` query parameter was omitted.
   - Cause:
     - `eq(column, converter, value)` called `converter.apply(value)` before checking whether `value` was empty.
   - Fix:
     - short-circuit before conversion;
     - do the same for collection-based `in(..., converter, values)`.

2. `IBaseMapper.selectList(ids, columns)` did not guard empty id sets.
   - Symptom:
     - `RESCUE-10` could fail with SQL `id IN ()`.
   - Fix:
     - return empty list when `ids` is empty.

3. Temp file delete + immediate reupload can collide on generated filename.
   - Symptom:
     - `RESCUE-03-reupload`
     - `LOST-03-reupload`
   - Cause:
     - generated temp filename depends on original filename plus current timestamp granularity; immediate reupload may reuse the same name before async file cleanup completes.
   - Fix:
     - adjust API test script to wait briefly before reupload verification.

4. Incremental runtime classpath became stale during repeated hot reruns.
   - Symptom:
     - `RESCUE-08` hit `NoClassDefFoundError: RescueTaskRecordResponse`.
   - Fix:
     - run explicit `clean compile`, verify generated class files, then restart server with fresh compiled output.
